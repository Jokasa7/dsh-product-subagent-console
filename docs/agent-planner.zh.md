# Agent 方案设计器

[English](agent-planner.md) · 简体中文

Agent 方案设计器会把目标转换为可审核的执行方案，并在执行后把方案与真实运行并列展示。

当任务包含可独立推进的分支、不同专长角色或明确依赖关系时适合使用它；简单任务仍可以保留为单 Agent 方案。

## 启用方案设计器

将方案工具添加到复制后的 **Agent 预设**：

```yaml
- id: agent-planner
  name: dsh-product-subagent-console/plan-tool
  config:
    toolName: design_subagent_plan
    executeToolName: execute_subagent_plan
```

保存预设，然后使用该预设新建对话。

## 从目标到执行

1. 打开**子代理 → 方案**，输入希望得到的结果。
2. 选择**生成方案**。当前对话只会创建草案，此时不会启动子 Agent；也可以直接手动新建草案。
3. 在画布上选择卡片，并在编辑器中完善方案。
4. 保存草案，然后运行预检。
5. 处理阻塞问题，并明确接受可以接受的警告。
6. 批准修订。已批准内容会锁定；需要继续修改时，请基于它创建新修订。
7. 选择**查看执行请求**，阅读影响提示，再选择**确认并发送执行请求**。该请求会作为当前对话中的可见消息发送，并绑定这个精确的批准修订。
8. 在**实时**跟随运行，并在**偏差**中检查方案与实际执行证据。

## 可编辑内容

- **方案** — 目标、成功标准、协作模式、优化目标、执行后端和总体预算。
- **角色** — 职责、边界、传输 Provider、模型路由、Agent 预设、上下文模式和允许的工具。
- **任务** — 说明、执行角色、风险、预期输出、完成标准、资源、预算提示和是否需要批准。
- **依赖** — “顺序”依赖只控制调度顺序；“传递上下文”依赖还会把上游结果传给后续任务。

资源声明使用 `frontend/auth`、`docs/readme` 这类相对标识。预检会据此提示并行任务是否可能同时修改同一资源。

## 预检

预检会用当前 DSH Profile 的能力检查指定的已保存修订，包括：

- 无效依赖或循环依赖；
- 实际并行批次与并发上限；
- 不可用的 Provider、模型路由、Agent 预设或工具；
- 不受支持的执行后端或能力；
- 预算与可能的并行资源冲突。

编辑草案后，之前的预检结果会失效，批准前需要重新运行。批准后若 DSH 能力发生变化，原批准修订不会被原地改写：请基于已批准内容创建新修订，保存草案，重新预检并批准该新修订，然后再请求执行。

## 从批准到权威执行

批准与执行是两个独立决定。只有第二次确认后，系统才会签发短时效、仅可使用一次的执行授权。启动 Workflow 前，Host 会重新核对 Session、方案修订、批准状态、能力摘要和预检结果；同一修订存在活动执行时会拒绝重复启动。

**偏差**会把已批准合同与本次运行创建的真实 attempts 并列展示。选择方案任务、attempt 或执行节点，可以查看状态、角色、时间、依赖、子会话标识、验证回执和一致性发现。需要停止或重做时，先在**恢复**查看影响预演；取消整个运行还需要独立的两步授权。

方案与执行快照默认随有界 Foundry 日志持久保存。Host 重启后，未完成工作会恢复为 `unknown`，不会猜测为成功。存储控制见[数据与隐私](data-and-privacy.zh.md)。

## 当前执行支持

- 已批准方案通过 DSH Workflow 执行。
- 一次 Workflow 执行当前需要全部角色使用同一个传输 Provider。
- 角色工具策略必须继承 Provider 默认设置；角色级工具白名单和 Agent 预设当前不可执行。
- 任务级批准点、任务级 Token 或成本提示当前不可执行。
- 只有所选 Provider 明确报告支持时，才能使用输出 Schema。
- 方案级 Agent 数量、并发和超时会被强制执行；请求数和 Token 限制可能仅作提示，成本上限当前无法强制。
- Agent Teams 当前不能作为可执行后端。
- v0.9 中 Retry 与 Fork 只提供恢复建议，任务级取消不可发送；只有取消整个 Workflow 可以真正发送。
- 历史 Recipe 证据不会绕过当前能力与权限预检。

安装或执行遇到问题时，请查看[故障排查](troubleshooting.zh.md)。
